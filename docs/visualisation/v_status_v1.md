# V1 implementation status

## Supported acceptance run

`v1:synthetic-strict-fifo-diverge` is generated by executing the existing
`LoadingEngine` against a five-link directed topology. Three unit packets cross
a strict-FIFO diverge while one receiving link is temporarily closed. The run
therefore contains same-tick ordering, a persistent queue, diverging route
intent, link transfers, and complete packet lifecycles. It finishes at tick 7
with 26 canonical events and three completed packets.

The layout is a declared non-geographic diagram. The run uses the
`legacy_packet_ltm_style` profile and is explicitly not a parity calibration
claim. Its validation notes record engine cache consistency, conservation, and
cumulative-count consistency.

## Implemented viewer features

- directed topology Canvas with occupancy and queue emphasis;
- presentation-only activity markers and explicit warning;
- exact play, pause, step, reset, seek, speed, tick, and seconds display;
- run, profile, topology, contract, validation, and completion provenance;
- link inspector with static metadata, membership, queues, and counts;
- packet inspector with declaration, route intent, realised path, and lifecycle;
- canonical event stream in source order;
- cumulative entry, exit, and storage chart sourced from Python;
- responsive desktop and narrow layouts;
- persisted artifact reload and GET-only local API.

## Known limitations

- V1 ships one small synthetic fixture, not yet a Sioux Falls or Anaheim bundle.
- Network coordinates are non-geographic; no map-accuracy claim is made.
- Canonical events do not yet carry movement-allocation traces, so V1 exposes
  declared movement IDs but not allocation approvals or rejection reasons.
- Replay states are stored for every tick. This is ideal for the acceptance
  fixture but should become chunked states or proven checkpoints for large runs.
- The frontend currently loads at most 10,000 canonical events in one page and
  reports an explicit error above that bound.
- Run comparison, authority-visible state, delayed observations, literature
  overlays, and live sanctioned execution are extension points, not V1 claims.

## Recommended V2 milestone

Add a bounded, persisted Sioux Falls replay using the same contract, then replace
per-tick full-state storage with chunked read-only replay projections and proven
checkpoint reconstruction. Add movement-allocation trace artifacts as an
explicit Python projection rather than inferring decisions from lifecycle events.
This gives realistic topology scale and node diagnosis before adding authority
belief or live execution.
