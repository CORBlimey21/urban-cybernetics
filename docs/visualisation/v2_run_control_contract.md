# V2 run-control contract

## Resource catalogue

`GET /api/v2/catalogue` returns `uc.visualisation.control.v2`. Each entry has a
stable ID, kind, name, semantic description, provenance, classification,
parameters with units/ranges/defaults, compatibility constraints, and warnings.
V2 declares two compatible resource families:

- `uc_synthetic_diverge_v1`, `UCSyntheticPhysicalProfile_v1`,
  `uc_synthetic_alternating_demand_v1`, `synthetic_one_second_v1`;
- `sioux_falls_tntp_v1`, `SiouxFallsPhysicalProfile_UC_Default_v1`,
  `sioux_falls_canonical_od_v1`, `sioux_profile_default_v1`.

The Sioux Falls profile is explicitly an engineering-assumption profile, not
empirical calibration. Its TNTP diagram layout is non-geographic.

## Run request and freezing

`POST /api/v2/runs` accepts only `RunRequestV2`. It contains declared IDs,
packet count, canonical-prefix selection, seed, tick policy, optional exact tick
duration, wall/tick limits, completion/stop/validation/replay/persistence
policies, and optional label/note. Extra fields are forbidden. The backend
rejects unknown and incompatible IDs before starting and rejects a requested
tick duration that differs from the declared profile value.

Acceptance immediately persists `request.json` with:

- full request and control-contract version;
- resolved topology, profile, and selected-demand hashes;
- requested and resolved tick duration plus the resolution rule;
- Git commit, seed registry, run ID, and UTC creation time.

The browser cannot supply a path or executable implementation. Runtime IDs are
generated by Python.

## Lifecycle

The main path is:

`created → resolving → setting_up → running → finalising → validating → complete`

Safe control paths are:

- `running → pause_requested → paused`;
- `paused → resume_requested → running`;
- `setting_up|running|pause_requested|paused|resume_requested → cancel_requested → finalising → validating → cancelled`;
- `running → timed_out` through finalisation/validation;
- active nonterminal states may transition to `failed` on an explicit error.

Illegal transitions raise an error and produce a rejected acknowledgement.
Commands carry a stable `command_id`; duplicate IDs return the prior result with
`duplicate=true`. Pause and cancel take effect only between engine ticks.

Cancellation retains a partial artifact. Existing canonical events, packet
metadata, unresolved counts, provenance, checkpoints, stop reason, and partial
validation remain inspectable. Cancellation never means deletion and does not
manufacture packet-level `cancelled` events.

## Safety boundary

The only write commands are create run, pause, resume, and cancel. There is no
generic mutation API. The orchestrator uses public loading/demand/topology
interfaces and does not change loading semantics. A browser disconnect has no
effect on the background Python executor.
